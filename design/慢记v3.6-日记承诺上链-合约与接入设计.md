# 慢记 v3.6 —— 日记与承诺上链：合约设计与接入说明

日期：2026-10-08。本文件描述 v3.6 新增的「公共链锚定」能力：本地永恒之链之外，把日记（contribution）与承诺（promise）的内容承诺自愿提交到 BOT Chain 主网合约 `ManjiEternalChain`。

## 1. 要解决的问题

v3.5 的永恒之链存证有一个诚实声明：「链由本应用在你自己的慢记服务里维护，尚未提交公共区块链」。也就是说，存证的可信度仍依赖本应用存活与诚实。v3.6 补上这一环：**任何人、任何时候，不依赖本应用，都能核验某条承诺确实在某时刻被登记过**。

同时必须守住《心动铃铛-关系上链隐私与退出机制研究》划出的红线：上公共链不能暴露正文、照片、成员身份或关系状态。

## 2. 两级链的分工

| | 本地永恒之链（v3.4–v3.5） | 公共链锚定（v3.6 新增） |
|---|---|---|
| 存什么 | 区块（PoW-lite）+ 承诺 + salt 台账 | 只有承诺哈希 / 本地链头部哈希 |
| 谁维护 | 用户自己的慢记服务 | BOT Chain 主网（合约 `0x9757b6fd…c627`） |
| 证明什么 | 内容指纹在应用内的完整演进史 | 该指纹在区块时间 T 已登记（全球可核验） |
| 撤回 | 本地链同样只追加 | 永久不可撤回（需用户二次自愿确认） |

两级链登记**同一个承诺值**：`commitment = SHA-256("manji-anchor-v1" ‖ canonicalJSON(内容) ‖ salt)`，由同一份代码计算（`server/domain/chain.js` 的 `commitmentOf`），不存在两套公式。

## 3. 合约设计（contracts/ManjiEternalChain.sol）

Solidity 0.8.24 / paris / 优化 200 runs，单文件无依赖，字节码 3454 字节。核心决定与理由：

1. **只收哈希**。写入接口仅三个：`seal(bytes32)`、`sealBatch(bytes32[])`（≤256，批量省 Gas）、`anchorHead(bytes16,bytes32,uint64)`（本地链头部锚定——一笔交易保护整条本地链历史）。存储、事件、输入参数里没有任何地址、文本或类型标记（连「这是约定还是日记」都不上链）。
2. **relayer 模型代替成员签名**。若把双方钱包签名发进合约，任何人都能从签名恢复出签署地址——等于把成员地址写进公开交易输入。因此：双方同意在链下核验（应用内强制），交易由统一代提交账户发送。合约只证明「承诺在 T 已登记」，不假装证明「登记时已获同意」——这是文档化的信任边界。
3. **append-only 到极致**。没有修改/删除/暂停/升级函数，无代理；`owner`（部署时固定、不可转让）唯一操作是 `setRelayer` 轮换代提交账户；relayer 私钥最坏情况只能登记垃圾哈希，无法触碰任何已登记数据；合约拒绝收款。密钥丢失只会让合约停止新增，不会影响已登记内容。
4. **防重登记**。承诺含 32 字节随机 salt，全局唯一；同值重复提交按 `AlreadySealed` 回滚（既省 Gas 也是「同内容同盐只有一条记录」的保证）。
5. **头部单调递增**。同一条本地链只能锚定更高高度（`HeadNotAdvancing`），「最新头部」语义成立。
6. **可核验读接口**。`sealOf(bytes32) → (found, index, sealedAt)` 是核心：任何人对任何浏览器/RPC 发起 eth_call 即可核验，无需登录、无需信任本应用。另有 `sealCount/sealAt/sealsOf/headOf`。

`anchorHead` 的 `localChainId(bytes16)` = `SHA-256(应用链编号 base64url 串)` 前 16 字节（确定性派生；应用链编号是随机串，非用户身份，导出文件已含它，第三方按同一规则可复算）。

## 4. 应用接入（全部零 npm 依赖，ethers 为可选）

```
用户流程：本地镌刻（v3.5 流程，共同约定须双方点「我也愿意」）
       → 用户明确点击「提交公共链」（第二次自愿确认，不自动上链）
       → 队列（public_seals / public_head_anchors 表）
       → auto 模式：后台 15s 循环批量 sealBatch 提交；manual 模式：给出 calldata 由运营者用任意钱包发送后回填交易哈希
       → eth_getTransactionReceipt + 链上 sealOf/headOf 双重复核确认（自愈：即使本地台账丢失，链上已登记的会被自动认回）
```

- `server/domain/keccak.js`：自带 Keccak-256（EVM 版）实现，载入时用公开向量 + **与 solc 编译输出的 7 个函数选择器逐一比对**自检，错则拒绝启动。
- `server/domain/public-chain.js`：calldata 组装/返回值解码/JSON-RPC/队列/签名广播。RPC 层 fetch 失败自动降级 curl（本机实测：主网节点对 Node TLS 指纹选择性丢包、curl 可通）；签名完全本地完成（ethers 仅做 secp256k1，可选依赖）。
- 提交防重：后台循环有互斥锁（一轮未完不开下一轮）；只有「成功问过链上且未登记」的行才允许提交——网络故障时宁可等下一轮，绝不盲发。
- `server/routes/onchain.js`：`GET /api/chain/onchain/status|/onchain|/verify/:id`、`POST /onchain/:id|/bind|/head`，权限沿用本地链详情的同一套判定。
- 机密（relayer 私钥）只存 `.env.local`：`server/config.js` 在 `.env` 之后加载并覆盖；`.env.local` 被 `.gitignore` 与交付打包双重排除。

## 6. 边界（诚实声明）

- 上链不证明内容为真、不证明感情真实、不证明登记时确已取得双方同意；同意过程在应用内完成，凭证由成员各自保存。
- salt 与正文永不离开链下；第三方拿到全部链上数据也无法枚举比对正文。
- relayer 地址与登记时间是公开可见的（统一专用账户、不关联用户身份；时间关联风险已在隐私研究中评估并接受）。
- 承诺一旦上链永久不可撤回；「退出权」体现在应用权限与展示层（v3.2 的暂停/解除关联），不承诺收回已公开的历史交易。
