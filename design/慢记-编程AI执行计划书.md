# 慢记｜可直接交给编程 AI 的完整执行计划书

版本：2026-10-07。产品名：慢记。英文项目标识可用 `Manji`。

**慢记是一间由回忆慢慢布置起来的家。小狗是陪伴者，一件纪念物可以藏着两个人对同一天的不同记忆。**

本次交付只有本计划书和 12 张手机 UI 设计图，不包含网站、程序、可运行原型或独立代码 Prompt 包。本文后半部分的开发任务由下一位编程 AI 执行，不表示本次已经实现。设计图是待开发界面的视觉方案，不是已经运行的软件截图。

## 1. 给下一位编程 AI 的任务合同

### 1.1 你要交付什么

在用户授权开始开发后，依据本文件和同包 `手机UI` 图片建立移动端优先的 Web 应用：真实账户与会话、一间家、一只可命名的小狗、照片与文字回忆、可手选的纪念物、独立保存的双人视角、轻量承诺、纪念日、收纳查找、免费基础电子纪念作品、隐私与退出。

首要验收不是房间多漂亮，而是：**A 放入一段回忆并选择纪念物；B 从另一独立账户加入，补上自己的视角；双方能再次点开这件物品，看到当前被允许共享的内容。** 不允许切换模拟昵称冒充两位真实用户。

你需要交付完整源码、后端和数据库初始化、受保护的媒体存储、运行说明、无密钥配置示例、实际测试结果和未完成项。本文是一份完整开发依据，无需旧项目、旧奖励代码、历史聊天或其他 Prompt 才能理解。

### 1.2 输入与优先级

1. 本文件中的“已明确决定”及业务、隐私规则。
2. 同包 12 张手机 UI 图；界面文案、字段和权限细节以本文件为准，不靠识别图片文字猜业务。
3. 原始《慢记-产品讨论总结.md》的产品动机与候选方向，已经在本文件转成可执行范围。
4. 原 Stitch ZIP 的视觉只用于奶油白、玫瑰金、留白、圆角和排版参考，不把参考 HTML 当作成品。

本包可以整体移到另一台电脑。以解压目录作为 `DELIVERY_ROOT`，图片使用相对路径；不要把作者电脑路径硬编码到应用里。新建项目独立存放，不覆盖用户此前的源码、ZIP 或设计交付。

| 项目 | 本版决定 |

| 视觉 | 优先原 Stitch 的奶油白与玫瑰金方向，覆盖讨论总结中的灰绿主配色建议 |

### 1.4 建议的 MVP 决策：不是用户已经逐项确认的规则

为让开发可执行，下列是本文件提出的首版建议。应在上线评审时确认；实现和测试中需明确记录采用了这些假设，不得宣传为已完成用户研究。

- 首版一人最多同时加入一个有效共同小家，可先单人使用；每家最多两名有效成员。
- 本版信息架构采用五个主导航“小家 / 回忆 / 承诺 / 纪念 / 我的”；这是设计决定，不声称用户已逐个确认 Tab。
- 一件回忆容器内，每人拥有一份独立贡献，可追加自己的版本与照片；每人的内容归本人控制。
- 首批提供 6 个手选纪念物模板，房间使用固定可选摆放点，不要求精细拖拽。
- 首版只做照片和文字；免费基础电子明信片放入 P0，语音及实体制作补贴放入 P1。
- 暂停是个人设置，不通知对方“你暂停了”；解除关联可以单方立即完成，共同小家冻结，双方分别保留自己的内容及小狗陪伴。
- 解除后不继续读取对方贡献、附件或过去生成的含对方内容的在线作品；不复制对方私密内容到自己的新空间。
- 年度 2 月 29 日纪念日在平年按 2 月 28 日提醒，规则在设置附近说明。

## 2. 产品价值、范围与一次完整体验

### 2.1 面向谁

优先面向本来就会拍照、收藏聊天片段、准备纪念日礼物，却缺少共同整理空间的人。两位成员的表达方式可以不同：一个人放照片，另一个人补一句话，也可以只有一人先用。

产品希望回答：“同一天，在你心里是什么样子？”它不判断感情深浅，不把使用频率当作爱意，不展示谁付出更多。

### 2.2 核心闭环

**留下一小段 → 手选纪念物 → 放进家里 → 邀请对方补充视角 → 点开物件回看。**

示例：A 上传海边照片，写“今天的风有点大”，选择贝壳并放在窗边。B 自愿补充“你一直护着我手里的冰淇淋”。下次点开贝壳，分别显示两人的原文与照片，不把两人的叙述合成为系统编造的共同事实。

物件外观、回忆容器、个人贡献和房间位置分别保存。换一个物件、收进盒子或挪到书架，不改变原始文字和照片。

### 2.3 P0 必须做

- 必要但简短的账户流程、单人小家、邀请另一人、明确接受。
- 一间房、一只可命名的小狗；点击、休息、玩球等轻量表现。
- 照片／简短文字、私密草稿、个人贡献版本、选择共享。
- 6 个纪念物模板、固定位置摆放、物件详情与双人视角。
- 回忆列表、日期／关键词／主题查找、收纳、个人隐藏与回顾开关。
- 不评分的轻量承诺；一次性／年度纪念日与站内提醒。
- 免费基础电子明信片、首次共同回忆的一次性外观。
- 个人免费导出、按版本授权的双人内容作品／导出、暂停与解除关联。
- 真实后端权限、私密媒体读取、持久化、错误重试和并发保护。

### 2.4 P1 与暂不建设

语音、未来信箱、共同愿望板、更多房间、扩展纪念册、可实际生成的短片以及实体印制可在核心流程稳定后安排。制作补贴必须等真实预算、供应商、活动名额与费用规则接入后开放。

首版不做复杂三维、付费生成式 AI、支付、公开广场、推荐排行榜或 NFT。数字凭证不是默认能力；没有用户价值论证和独立自愿授权前不接入。原文、照片、身份信息不上链。

语音不在首版编辑器里画成可以点击的录音按钮。未来功能若需说明，放在清楚标记的介绍文字中，不伪造可用操作。

## 4. 三类记录、纪念物与小狗

### 4.1 首次使用：先放回忆，再邀请

必要账户步骤后，选择一只默认小狗并起名；首版仅需少量外观选择，不设置抽卡。用户放一张照片或一句话，选择纪念物和位置，即可看到自己的第一段回忆。此时内容默认仅自己可见。

完成后才温和出现“想邀请一个人，补上同一天的另一面吗？”用户可跳过。邀请中的照片／原文必须由发起者另行选中并预览；复制链接本身不等于把全部记录授权给持链人。

**默认私密时，摆进家里的物件属于本人私有展示层。** 即使当前已经与伴侣共用一间家，另一方也看不到该物件、标题、缩略图、位置变化或记录数量提示。只有作者主动选择共享并确认预览后，才将允许的物件入口与贡献放到共同展示层；不能出现“文字私密，但物件已经向对方透露这段回忆”的泄露。

### 4.2 回忆与个人贡献

- 一条回忆容器保存事件日期、主题、物件关联等共同框架；个人文字与照片分别保存在贡献表中。
- 贡献可以仅文字、仅照片或两者都有，不要求写长文。建议首版每人每件回忆最多 6 张照片，单张不超过 10 MiB；允许 JPEG / PNG / WebP，前后端均检查真实文件类型与解码结果。
- 单份正文最多 500 字，编辑器显示计数；标题非必填，可从本人文字截取可编辑短标题，不能让 AI 编造经历或情绪。
- 发生日期默认业务今天，可补记过去；未来计划放在承诺或纪念日中，不把未发生事件写为既成事实。
- 编辑只创建本人的新版本。对方的内容与作者信息不得被另一成员覆盖。
- 将本人贡献设为共同可见需要主动选择。取消共享立即使对方失去访问该贡献和附件的权限，不需要对方同意。
- 一条共享回忆可以只有一个人的贡献；另一方可以只补一句，也可以不补。不得显示“你比对方少记了多少”。

### 4.3 首批 6 个纪念物模板

| 模板 | 可表达的经历示例 | 推荐位置，仅供选择 |
| --- | --- | --- |
| 贝壳 | 海边、湖边、一次出游 | 窗台 |
| 电影票 | 看电影、演出、一起追剧 | 沙发旁的小桌 |
| 小锅 | 一起做饭、第一次失败的菜 | 厨房角落 |
| 雨伞 | 雨天接送、一起散步 | 门口伞架 |
| 小帐篷 | 露营、野餐、户外一天 | 房间角落 |
| 咖啡杯 | 早餐、聊天、加班时的陪伴 | 茶几 |

推荐不是自动决定；用户随时可改。首版固定模板和摆放点足够，不依赖图像生成或三维建模。选择“暂时收纳”也能完成记录，不强迫房间放满。

**纪念物是记录的入口，不是新的内容所有者。** 换模板、换位置、放入盒子均不生成另一份照片或复制另一位成员的贡献。

房间按当前用户渲染“共同层＋本人私有层”。私有摆放与共同摆放分开保存位置占用，不因对方私有物件占位而返回可猜测的提示。私有层只有本人能移动、收纳、搜索；共享贡献被全部撤回后，共同层不得继续留下带有原私密标题或缩略图的空物件。

### 4.4 小狗陪伴与回顾

小狗可休息、玩球、躺在垫子上、回应点击。与已经记录的主题产生轻关联时，必须基于真实已有标签，例如有露营记录后出现帐篷附近活动；不推断“你们感情更好”。

没有日更、饥饿值、断签、健康处罚、缺席悲伤或成长加速。获得外观不会使小狗长得更快，未参加活动不会让小狗受损。

首版回顾是用户进入时可选择查看的旧物卡，不做强推送。候选每次都经过当前授权、个人隐藏、回顾排除、删除状态和空间状态过滤。用户可关闭全部回顾或排除某条。被隐藏、撤权或删除的内容不能被搜索推荐、回顾缓存、通知预览或小狗带回功能重新暴露。

### 4.5 收纳、隐藏和删除是不同动作

| 动作 | 影响 | 不允许发生的事 |
| --- | --- | --- |
| 收纳物件 | 改共同房间的摆放状态，记录仍在；任一有效成员可收纳，界面说明对双方房间生效 | 不删照片、贡献或搜索记录 |
| 从盒子放回 | 使用选定位置恢复展示 | 不复制出第二份回忆 |
| 个人隐藏 | 仅本人默认列表和回顾不再出现；可在隐私管理中恢复 | 不通知或替对方隐藏；不能通过推荐重新出现 |
| 撤回本人共享 | 对方立刻失去本人贡献及附件访问，本人保留 | 不删除对方贡献；不保留对方可用的缩略图缓存 |
| 删除本人贡献 | 本人版本与媒体按删除流程不可再访问，保留最小无正文审计标记 | 不能连带删除另一人的记录 |
| 共同移除回忆容器 | 两人明确同意当前容器版本后，移除共同入口和物件，原始个人贡献回各自私密档案 | 不以“删除容器”绕过另一人的内容所有权 |

“共同移除”确认框必须直说“共同入口将移除，各自原始内容仍由本人管理”。如果需要彻底删除原始内容，由各作者分别执行删除；一人的同意不能替另一人删除。

共同移除只管理共同结构，不能阻止个人独立撤权、删除本人的贡献或解除关联。本人私有层的物件由本人移除，无需对方同意。

### 4.6 轻量承诺

字段为一句约定、可选的日期、个人／共同范围及简短补充。不要强制验收材料、积分、责任评级或复杂审批。

个人承诺本人管理；共同承诺可先提出，由另一人点击“我也愿意”后成为共同约定。对方不回应不会阻止日记、房间和小狗使用。支持改期、暂停、收起和记录完成。

首版建议状态：`proposed / active / completed / paused / archived`。共同约定的重要文字或日期修改需让对方重新确认；日常结果可由一方标记“我记下这件事已完成”，保留操作者，避免冒充双方对事实作正式证明。另一方可撤销该完成标记并补充说明，界面用“再聊聊这件小事”，不判违约。

承诺不会自动变成回忆。完成后可提供“把这一天留下来”，由用户自己补充真实内容、选择物件与共享范围。

### 4.7 纪念日

独立保存名称、日期、一次性／每年重复、提醒偏好与范围；允许未来日期。默认按 Asia/Shanghai 业务日期计算，数据库保存日期字段，不用浏览器 UTC 解析导致偏移一天。

今天显示“就是今天”，过去的一次性事件显示“已过去”，年度事件计算下一次公历日期。首版提醒可选不提醒、当天或提前 1 / 3 / 7 天，先做站内提醒；不宣称系统推送已经接通。修改／删除时取消旧待发提醒，重复执行任务不重复通知。

纪念日只是日期提醒，不自动启动活动、发放补贴或生成作品；用户点击“做一份纪念”才进入内容选择。

## 5. 新奖励：作品、外观与后续制作补贴

### 5.1 首版规则

| 形式 | P0 决定 | 状态与边界 |
| --- | --- | --- |
| 基础电子纪念作品 | 免费生成单页电子明信片；选择模板、照片与原文，输出可下载 PNG | 本人内容可独立制作；含对方内容需对当前版本和此次用途授权 |
| 首次共同回忆外观 | 同一回忆中，两位有效成员各自自愿分享至少一份有效贡献后，自动获得一次性名字牌或小沙发外观 | 不要求公开、不要求等量、不要求连续记录；只授予一次，重复请求不重复发放 |
| 房间主题／小狗配饰 | 可提供免费基础样式；后续付费外观需另行明确 | 不锁核心功能、不提高成长速度、不制造落后感 |
| 制作补贴 | P1，等待真实预算、供应商、名额与活动规则 | P0 只显示“活动开放后查看”，不能编造金额、中奖名单、可领取券或到账 |

外观权益只记录授予事实，不保存触发回忆正文。用户之后隐藏、撤回共享或解除关联，不追讨已经获得的外观；避免用奖励强迫继续暴露内容。解除后各人可在个人小家使用已授予自己的外观。

“首次共同”只是一次可选体验的条件，不变成贡献评分。一个人使用时仍有完整记录、基础外观和免费个人电子作品；没有双人外观也不影响小狗状态。

### 5.2 作品生成与授权

流程：选择当前有权使用的贡献版本 → 预览实际将出现的文字与照片 → 若含对方贡献，请其确认此次版本与用途 → 发起生成任务 → 查看真实进度 → 成功后下载。

首版只做基础模板排版，不依赖生成式 AI。不能以一张预览图宣称短片或实体作品已制作。用户编辑、撤回共享或删除内容后，尚未完成的作品授权立即失效；已生成但仍由系统托管的文件停止下载并清理相关预览。已经被他人下载的文件或截图无法收回，授权前明确说明。

P0 以私密下载为主，不建立公开分享广场。将文件用于对外发布，需要双方对实际选中内容和发布用途明确同意；下载授权不能被解释为无限制公开许可。产品不承诺技术上控制已经离开系统的文件。

### 5.3 P1 补贴开放条件

活动开放前，运营必须配置真实活动标识、供应商、可用名额、费用／运费、申请资格、有效规则、隐私与撤销路径。后端确认名额与履约状态后，UI 才能显示对应可申请／处理中／完成状态。

当前没有这些接入，按钮不能写“立即领钱”“已经到账”或展示虚构货币金额。推荐新情侣、邀请榜、每月推荐次数上限等在原讨论中是候选方案，本版不作为已确定权益实现。

## 6. 隐私、导出与关系生命周期

### 6.1 权限原则

私人草稿只有作者看得到，包括标题、缩略图、附件和是否存在；不通知伴侣。建立共同关系不自动公开历史。共享一件回忆不意味着永久授权全部版本、外发或导出。

每人只能改自己的贡献。共同元信息如物件模板、日期与房间位置使用独立版本控制。涉及将对方内容制作作品、下载打包或对外发布，授权绑定**具体贡献版本集合＋用途＋接收范围**；不能用一次泛化勾选覆盖未来内容。

不展示最后在线、阅读次数、贡献排名、对方未完成列表或“谁更爱谁”。记录数量仅可作为个人查找辅助，不能转成关系判断。

### 6.2 导出与作品授权矩阵

| 内容／用途 | 本人可以做什么 | 是否需要另一人同意 |
| --- | --- | --- |
| 本人私密／已共享贡献 | 免费导出文字与原始附件；生成个人基础作品 | 不需要；不能夹带另一人的内容 |
| 对方共同可见贡献 | 在有效共同空间中读取 | 查看授权不等于导出／外发授权 |
| 包含对方贡献的作品或打包下载 | 选择具体版本，发送明确授权请求 | 需要对方确认；拒绝后可改为仅本人内容 |
| 对外公开两人内容 | 预览实际内容和用途，获得双方明确同意 | 需要；改版、换用途后重新确认 |
| 退出后的本人内容 | 从个人档案免费导出 | 不需要，也不受共同空间冻结阻挡 |
| 隐藏／已撤权／删除的对方内容 | 不可生成、预览、下载或推荐 | 不能拿旧授权绕过当前撤权 |

个人导出至少提供 UTF-8 JSON／Markdown 与本人的附件原文件，可打包 ZIP；不锁在付费计划中。作品 PNG 与个人数据导出是不同入口。所有后台任务启动、执行、完成下载时再次验权，不能只在点击时查一次。

### 6.3 暂停

暂停是个人选择：关闭提醒、暂停回顾、减少动画或暂时隐藏共同空间。不改变对方的设置，不向对方发出“对方不再参与”通知，不处罚小狗，也不删除内容。恢复时仅恢复本人允许的开关，不自动重新共享已撤回的内容。

### 6.4 解除关联：建议的 MVP 决策

以下为本计划书给出的可实施方案，尚不代表用户已逐项确认，应在上线评审中确认其文案和保留规则。

1. 任一成员本人确认后立即解除，不等待对方批准，不要求删除回忆，也不把作品授权、外观或活动进度当作阻碍。
2. 共同小家冻结，双方对旧共同空间的交叉内容访问立即撤销；待邀请、待共享、待外发授权和含对方内容的生成任务取消。不能只隐藏前端入口。
3. 每人保留自己的贡献与附件，在本人私密档案中继续查看和免费导出；不取走、改写或删除另一人的内容。
4. 旧共同容器可以保留最小结构用于各自定位自己的记录，但接口只能返回本人的内容和安全元信息，不返回对方原文、缩略图或敏感标题。若标题来自对方且无本人授权内容可展示，使用“已归档的回忆”等中性名称。
5. 双方分别延续小狗陪伴，可保留共同选定的小狗外观与名字；不复制对方私密回忆或旧共享授权。两人的新个人小家从各自有权内容重新布置。
6. 已下载文件、截图等副本无法追回；解除界面说清系统能撤销的是后续同步、在线查看、附件访问和托管下载。
7. 未完成活动或外观不影响退出。将来实体订单若接入，其履约与退款需独立规则，本版不假设已经存在。

承诺与纪念日遵循同样的退出边界：本人创建的条目转入本人私密档案，对方创建的条目停止访问，不代替对方删除；原共同承诺的协作、待确认动作冻结，不自动判任何一方失约。原共同纪念日提醒全部取消，用户可在自己的私密条目中重新开启个人提醒。退出前已经排队的共享通知、提醒与预览在发送前再次验权，不得泄露对方条目名称或内容。

服务端以同一事务先提交解除与撤权，后续清理可以异步完成，但清理尚未完成不能让旧内容继续被读取。活动任务和通知发送前都检查空间是否仍有效。

## 7. 建议架构与数据字典

本节是交给下一位编程 AI 的实施要求。本次未创建代码、接口、数据库或存储。建议采用团队熟悉的 TypeScript Web 技术及关系型数据库，不绑定未经检查的依赖版本。最小结构为：移动端页面 → 服务端会话与授权 → 领域服务 → 事务数据库／私密媒体存储／后台任务。

### 7.1 分表模型

| 对象 | 核心字段 | 关系与约束 |
| --- | --- | --- |
| User | id、displayName、createdAt | 身份来自 session；不信任请求体 userId |
| Session | id、userId、expiresAt、revokedAt | 独立账户会话；退出登录和服务端撤销有效 |
| Home | id、status、timezone、revision、createdAt、frozenAt | `solo / shared / frozen`；最多两名有效成员 |
| Membership | homeId、userId、status、joinedAt、leftAt | 绑定资格通过事务／唯一约束控制 |
| Invite | id、homeId、creatorId、tokenHash、expiresAt、status、previewGrantId? | 一次性高熵令牌；仅摘要入库；不自我接受、不重复消费 |
| PetProfile | id、ownerType、ownerId、name、appearanceKey、settings | ownerType 为 home / user；无饥饿、感情或惩罚分数 |
| MemoryContainer | id、homeId?、creatorId、eventDate、topic、safeTitle、visibility、status、revision | `private / home`；只放事件框架；私密元信息不向对方返回，共同容器移除需明确授权 |
| Contribution | id、memoryId、authorId、visibility、currentVersion、deletedAt | 每人拥有自己的贡献；`private / home`；作者独立撤权与删除 |
| ContributionVersion | contributionId、version、text、createdAt、contentHash | 版本只追加；hash 用于版本比对，不声称已上链 |
| MediaAsset | id、ownerId、versionRef、storageKey、mime、size、status | 私有存储；绑定贡献版本；缩略图沿用同样权限 |
| ObjectTemplate | key、label、assetRef、allowedSlots | 6 个固定模板；不含用户照片 |
| MemoryObject | id、memoryId、templateKey、ownerId、visibility、revision | 纪念物选择与贡献内容分开；私密物件本身也受权限控制 |
| Placement | id、homeId、objectId、layer、ownerId?、slotKey、status、revision | layer 为 private / home；私有层按用户隔离，状态为 displayed / stored；收纳不动贡献 |
| MemberMemoryPreference | userId、memoryId、hidden、excludeFromRecall | 个人隐藏和回顾排除；不替另一人设置 |
| Promise | id、homeId?、authorId、text、dueDate?、scope、status、revision、actedBy | 轻量约定；共享改版后重新确认，不生成评分 |
| Anniversary | id、ownerId、homeId?、title、date、repeat、reminderDays、scope、revision | 独立日期实体；未来日期合法 |
| ConsentGrant | id、requesterId、approverId、resourceVersions、purpose、audience、status、revision | 对具体版本及用途授权；变化／撤权立即失效 |
| WorkJob / WorkArtifact | id、ownerId、versionSet、grantIds、templateKey、status、artifactKey | `queued / running / ready / failed / cancelled`；下载再次验权 |
| AppearanceGrant | id、userId、homeId、appearanceKey、reason、businessKey | 唯一授予键，记权益不存私密正文；无货币余额 |
| Reminder / Notification | id、userId、sourceId、occurrenceDate、dedupeKey、status | 发送前验权与排除，重试不重复发送 |
| AuditEvent | id、actorId、action、objectId、revision、at、result | 最小审计；无完整正文、照片、邀请码明文或密钥 |

### 7.2 关键关联

- 一个 Home 连接 Membership、PetProfile、MemoryContainer 和 Placement；一个用户有自己的个人空间与最多一段有效共同绑定。
- 一个 MemoryContainer 可以有两人的不同 Contribution；每份 Contribution 有多个 Version，媒体挂到具体 Version。
- MemoryObject 指向容器；Placement 只指向物件及位置，并区分共同层与本人私有层。收纳、替换物件、删除个人贡献是三个独立命令。
- ConsentGrant 绑定版本集合；WorkJob 固定输入版本，但执行和下载仍检查当前授权，固定快照不能规避撤权。
- 除 Activity P1 外，不建立旧点数、投入、婚姻核验或奖励争议表；AppearanceGrant 是外观权益，不是金融账本。

## 8. 核心 API、权限和可靠性

### 8.1 统一命令契约

身份只能来自服务端会话。每个查询和每个写操作检查归属、成员状态、内容范围与对象状态，不能依靠隐藏按钮。

写操作使用 `Idempotency-Key`，更新使用 `expectedRevision`。同一身份、同一路由、同一键和相同负载的重试返回原结果；相同键不同负载返回冲突。先验证输入、权限与状态，再执行事务，不能非法请求也写下一半记录。

成功返回 `{ data, revision?, requestId }`；错误返回 `{ error: { code, message, fieldErrors?, retryable }, requestId }`。未登录返回 401、越权 403、版本或业务冲突 409、字段错误 422、暂不可用 503；对不应暴露存在性的私密对象可统一返回不泄露信息的 404。

### 8.2 命令与授权表

路径为建议契约，可调整命名，但必须保持对应行为并记录映射。

| API／命令 | 输入与作用 | 必须执行的授权／状态约束 |
| --- | --- | --- |
| GET `/api/me`；POST `/api/homes` | 当前身份；创建单人家 | 不凭前端参数冒充他人，重复创建幂等 |
| POST `/api/homes/:id/invites` | 创建邀请，选择可选预览内容 | 仅有效单人成员；预览只能含本人主动授权的具体内容 |
| POST `/api/invites/accept` | token、明确接受 | 验证有效期、未撤销／未消费、不是本人、双方无绑定冲突；事务建立成员资格 |
| POST `/api/invites/:id/revoke` | 撤销 | 只有发起者；撤销后任何旧链接均不可加入 |
| GET/POST `/api/memories` | 查询当前可见内容；创建容器与本人贡献 | 私密默认；不是先创建公开容器再补权限 |
| POST `/api/memories/:id/contributions` | 添加本人视角 | 当前有权进入容器；不能设置 authorId 为他人 |
| PATCH `/api/contributions/:id` | 创建本人新版本 | 作者本人、expectedRevision；对方版本不受影响，相关授权失效 |
| POST `/api/contributions/:id/share`、`/revoke` | 主动共享或撤回 | 仅作者；有效成员关系；撤回立即断开媒体与作品访问 |
| DELETE `/api/contributions/:id` | 删除本人贡献 | 仅作者；仅处理本人内容；不级联删除对方贡献 |
| POST `/api/memories/:id/removal-requests`；`/approve-removal` | 请求／确认移除共同容器 | 绑定容器版本，双方明确同意后移除共同入口，个人内容转私密档案 |
| POST `/api/media/uploads`；`/complete` | 授权上传、验证完成 | 限定本人、用途、大小、类型；未完成上传不可作为已保存图片 |
| GET `/api/media/:id` | 原图／缩略图／下载 | 每次检查当前内容权限；不能通过公开 URL 绕过撤权 |
| PUT `/api/memories/:id/object` | 手选模板 | 当前有效成员，模板白名单、版本校验；不改正文 |
| PUT `/api/placements/:id` | 移动／收纳／放回 | 共同层限有效成员，私有层限作者本人；不能摆放本人无权读取的内容；独立层级和位置版本 |
| PUT `/api/me/memory-preferences/:id` | 个人隐藏／排除回顾 | 只修改本人设置；立即使相关回顾与通知候选失效 |
| GET `/api/recall`、`/api/search` | 回顾或查找 | 查询阶段和返回阶段均过滤授权、冻结、删除、个人隐藏与排除 |
| GET/POST/PATCH `/api/promises` | 约定及状态动作 | 个人作者／共同成员分开检查；不能冒充对方确认 |
| GET/POST/PATCH/DELETE `/api/anniversaries` | 日期、重复、提醒、范围 | 日期业务语义统一；修改取消旧提醒；私密条目不通知伙伴 |
| POST `/api/consents`；`/:id/respond` | 指定版本、用途、范围；接受／拒绝 | 只能邀请内容权利人授权；过期版本或已撤权内容不能批准 |
| POST `/api/works`；GET `/:id`、`/:id/download` | 生成／查询／下载基础作品 | 提交、工作进程与下载三次验权；不允许把旧生成任务变成绕权通道 |
| POST `/api/exports`；GET `/:id/download` | 本人数据或获准版本打包 | 本人导出免费；别人的内容必须有明确当前授权 |
| PUT `/api/me/preferences` | 暂停通知／回顾、减少动画 | 仅本人设置；不公开暂停状态 |
| POST `/api/homes/:id/unlink` | 本人明确确认解除 | 单方即可；立即撤销交叉授权、冻结空间、取消待办，不等待对方 |

所有接口路径都只是待实现契约，不是本次已运行的接口。

### 8.3 必须解决的失败与并发

- **保存与恢复**：服务端事务成功后才显示完成。失败保留用户输入；离线草稿明确标记只在当前设备。登录切换时草稿隔离，退出登录不把上一位用户草稿展示给下一位。可恢复草稿需明确用户选择，不默默保存所有私密内容到共享设备。
- **媒体一致性**：上传先进入隔离暂存，校验成功后绑定版本；贡献保存失败时不能生成可访问的孤儿公开文件。孤立暂存文件可后台清理，不删除已确认引用。
- **媒体撤权**：不得使用长期有效、任何持链者可读的私密附件 URL。采用后端鉴权代理等可立即撤权路径；缩略图、响应缓存、CDN 和作品预览同样受控。浏览器已下载副本无法收回，应如实说明。
- **双人编辑**：分别保存自己的 Contribution；共同元信息与摆放使用 revision。竞争同一摆放点时返回冲突和可选位置，不覆盖内容。
- **邀请竞争**：两人抢用邀请、重复接受、接受另一份邀请同时发生时，事务和唯一约束只允许合法一对。邀请令牌不可预测，不在日志输出明文。
- **外观幂等**：首次共同回忆事件可被重复投递，但每个家对应的一次性外观只授予双方各一次。发放记录不与继续共享绑定。
- **撤权与生成竞争**：用户撤权、删除或解除与生成任务并发时，撤权后的下载必须被拒绝；旧 job 就算完成，也不能恢复已失效授权。
- **提醒与回顾重放**：每个用户、来源和发生日使用唯一键；发送前再次检查隐藏／撤权／暂停，取消的条目不因重试复活。
- **恢复**：进程重启后记录、成员权限、媒体引用、授权撤销与任务状态保留；不能用内存仓库宣称长期保存。
